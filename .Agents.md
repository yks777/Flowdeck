## 1. O que é o Flowdeck

Plugin da barra do **Omarchy** (`id: yks.flowdeck`) com timers de foco,
quadro de tarefas e estatísticas. Tipos: `service` + `bar-widget` + `panel`
(`keepLoaded: true`, ver `manifest.json`).

Abas do painel (`Panel.qml`):

- **Focus** — timer Pomodoro (25/5/15, long break a cada 4) ou Flowtime
  (contagem crescente, interrupções, sugestão de pausa tradicional ou
  proporcional). **Não há seletor de técnica aqui**: a técnica vem de
  Settings (ver regra em §4).
- **Matrix** — matriz de Eisenhower (`Q1 DO | Q2 SCHEDULE | Q3 DELEGATE |
  Q4 DELETE`), board único. Botão **Focus** do card usa a técnica do
  Settings. Concluídas vão para o popup `Completed` (com busca).
- **Stats** — resumo do dia, barras da semana, histórico de sessões com
  filtro, streak.
- **Settings** (engrenagem no header) — durações, política de pausa,
  meta de streak, notificações, export/import/reset. Seção **Focus →
  Technique** (`settings.focusAction`) é a **única fonte da verdade**
  sobre qual técnica usar.

Stack: **QML + JavaScript puro** (arquivos `.js` com `.pragma library`).
Sem build, sem dependências, sem testes automatizados — o teste é
manual via shell rodando (ritual obrigatório em §6).

## 3. Arquitetura e invariantes (não quebrar)

- **Service.qml é o único dono do estado.** `Panel.qml` e `BarWidget.qml`
  nunca mantêm cópia concorrente: leem propriedades do Service e chamam
  seus métodos. `revision` (qualquer mutação) e `tickVersion` (tick de 1s)
  forçam recomputação das views.
- **Tempo sempre por wall-clock** (`deadlineMs`, `startedAtMs`,
  `accumulatedMs`). O tick visual NUNCA é fonte de verdade — é assim que
  o timer sobrevive a fechar painel, reload da shell e suspend.
- **`Model.sanitizeState` nunca joga exceção.** Estado corrompido vira
  backup `state.json.corrupt-<ts>` + blank seguro. `parseOrNull`-style:
  importar só aceita backup válido de verdade.
- **Persistência com debounce:** mutações chamam `saveSoon()` (800 ms) ou
  `saveNow()` em eventos críticos (fim de fase, import). `bump()` sozinho
  **NÃO persiste** — se mudar estado sem salvar, a escolha se perde no
  reload (foi exatamente esse o bug do toggle do Focus).
- **`timer` é parte do estado salvo**, junto de
  `settings/boards/tasks/sessions/activeBoardId/activeTaskId`.

## 4. Regra de produto: técnica vêm do Settings

- `settings.focusAction` (`"pomodoro"` | `"flowtime"`, sanitizado em
  `Model.sanitizeSettings`) é persistido via `updateSettings()` e é a
  **única fonte da verdade**.
- `FocusView.technique`: sessão ativa (`running/paused/break`) mostra seu
  próprio `mode`; **idle mostra `settings.focusAction`**.
- `Service.updateSettings` alinha `timer.technique` quando o timer está
  `stopped`; `stopTimer()` preserva a escolha do Settings no blank;
  IPC `start()` (Super+H) usa `settings.focusAction`.
- Nunca reintroduza seletor de técnica na aba Focus nem leitura de
  `timer.technique` como default idle.

## 6. Ritual de teste OBRIGATÓRIO após toda edição de código

Toda tarefa que altera `.qml`/`.js` **só está pronta após testar de verdade
e olhar screenshot**. Sem exceção. Passos:

1. **Validar o plugin:**
   ```bash
   omarchy plugin validate "/home/yks/Projects/Omarchy/Plugins/FlowDeck"  # exit 0
   ```
2. **Checar a lógica tocada com `node`** (os arquivos de `logic/` são JS
   puro; adapte ao que foi mudado):
   ```bash
   node -e '...'   # ex.: sanitizeSettings preserva focusAction; valor inválido cai no default
   ```
3. **Sincronizar com o instalado** (ver §2) e **reiniciar a shell**
   (a Service carrega na inicialização — sem restart o QML novo não roda):
   ```bash
   omarchy restart shell; sleep 6; omarchy-shell shell ping  # espera "ok"
   ```
4. **Abrir a view afetada via IPC e tirar screenshot:**
   ```bash
   omarchy-shell yks.flowdeck focus   # ou: matrix | stats
   sleep 2; grim /tmp/opencode/<nome-do-teste>.png
   ```
   IPC útil: `togglePanel, focus, matrix, kanban (alias), stats, start,
   pause, stop, finish focus|break, interrupt, status, today, isOpen, ping`.
   `Super+H` chama `togglePanel`.
5. **Ler a imagem e conferir visualmente** (a ferramenta de leitura exibe
   PNG). Só marque como pronto se o screenshot mostrar o comportamento
   esperado. Teste os dois lados de qualquer condicional alterada
   (ex.: técnica pomodoro **e** flowtime).
6. **Não deixe o ambiente alterado:** se precisar simular um cenário
   mexendo em `~/.local/share/flowdeck/state.json`, faça backup antes,
   restaure depois e reinicie a shell de novo. Confirme no fim com
   `omarchy-shell yks.flowdeck status`.

### 6.1. Regra de segurança do `state.json` (incidente real)

 mexer no `state.json` com a shell rodando + `restart shell` em sequência
já causou **perda das sessões** uma vez (o arquivo foi regravado sem elas;
só o backup salvou). Por isso, ao tocar no estado:

- Backup **antes**: `cp state.json /tmp/opencode/state-backup-<data>.json`
- Após qualquer restore + restart, **verifique na hora**: contar
  `sessions` no arquivo E via IPC
  (`omarchy-shell yks.flowdeck today` tem que mostrar os números
  de antes). Só prossiga se os dois baterem.
- Nunca edite o `state.json` e reinicie a shell no mesmo comando sem
  checar o resultado depois.

> Exceção: este próprio `.Agents.md` e `README.md` (só texto) dispensam
> restart/screenshot — basta reler o arquivo. Qualquer `.qml`/`.js`,
> mesmo de 1 linha, segue o ritual completo.
